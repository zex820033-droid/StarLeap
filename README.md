## 本地运行

```sh
pnpm install
pnpm dev
pnpm build
pnpm preview
```

开发地址：**http://127.0.0.1:4321/**。本轮沿用已运行的服务，确认热更新后的 `hero-evidence` / `evidence-grid` 页面及自托管字体均 HTTP 200；没有停止原进程或另起端口。

`pnpm build` 包含 Astro 检查、静态构建、`scripts/make-portable.mjs`（把资源 URL 改为相对路径）和 `scripts/verify-static.mjs`。无需 UI、动画或滚动框架：现有 Astro、CSS Grid、原生 details、IntersectionObserver 导航和前端表单校验足以完成本轮。

构建产物 `dist/` 是可独立浏览的静态站点：页面、样式、字体和图片都在 `dist/` 内，图片用相对路径引用（如 `_astro/xxx.webp`），不依赖 `src/` 或本机绝对路径。直接打开 `dist/index.html` 也能看到完整图片。

## 部署到 GitHub Pages

1. 把本项目（`xiaoguan-site/`）推到一个 GitHub 仓库，默认分支用 `main`。
2. 打开仓库 **Settings → Pages**，把 **Source** 设为 **GitHub Actions**。
3. 之后每次 `git push` 到 `main`，`.github/workflows/deploy.yml` 会自动 `pnpm build` 并发布 `dist/`。

构建时用两个环境变量决定 SEO 里的正式地址（页面资源本身始终是相对路径，所以改仓库名不影响图片）：

| 变量 | 作用 | 项目站点示例 |
| --- | --- | --- |
| `SITE_URL` | canonical / OG / sitemap 的站点根 | `https://用户名.github.io` |
| `BASE_PATH` | 仓库子路径（用户站点留空） | `/仓库名` |

工作流会根据仓库自动填好这两个变量，一般不用手动设置。本地 `pnpm dev` / `pnpm preview` 仍用 `http://127.0.0.1:4321/`，行为不变。
